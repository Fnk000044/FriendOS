## 一、参赛定位建议

### 1.1 两条路径对比

| 维度 | 主赛道 · 主题三（开放创新探索） | 揭榜挂帅 · 第 9 题（AI 心理健康陪伴与早期风险识别助手） |
|---|---|---|
| 主题契合度 | 泛"AI 创新"，需自证创新点 | **命题级契合**：陪伴 + 早期风险识别 = 产品两大核心，几乎是对题作答 |
| 提交形式 | 源代码 + 可执行程序，ZIP ≤ 100M | 申报书 + 演示视频 + 佐证材料（系统链接 / 可执行程序 / 可视化成果） |
| 体积约束 | **硬伤**：解压版 ~481MB、安装包 ~171MB、情感模型 ~100MB，几乎无法压进 100M | 无 100M 硬性限制，可执行程序仅作为"佐证材料"之一 |
| 平台要求 | 需兼容 Windows/Linux/Android/iOS | 未强制跨平台（当前仅 Windows 可接受） |
| 竞争格局 | 开放选题，泛 AI 项目涌入，评审注意力分散 | 定向选题，评审有明确期望，产品是"现成的高完成度答案" |
| 晋级名额 | 前 10 进决赛 | 前 5 进决赛 |

### 1.2 推荐结论

**主推：揭榜挂帅赛道 · 第 9 题「AI 心理健康陪伴与早期风险识别助手」。**

理由（按优先级）：

1. **命题契合度是最大杠杆**。产品 README 的两个标题级能力——「AI 对话陪伴」与「主动风险预警 / 早期风险识别（EarlyWarningService + 情感分析 + 风险评分）」——与第 9 题的两个关键词逐一对应。评审对该题有预设期望，产品不需要"说服评委为什么算 AI 创新"，只需要"证明把这道题做透了"。
2. **绕开 100M 体积硬伤**。主赛道主题三的 ZIP ≤ 100M 对 Electron 桌面应用是结构性冲突，压缩成本高、风险大；揭榜赛的提交形式对当前体积友好。
3. **完成度即优势**。产品已有打包版、离线冒烟测试、42 个单测、模型卡 / 风险方法论 / 外部验证报告——这套"工程 + 学术双佐证"正是揭榜赛需要的"佐证材料"。

### 1.3 取舍分析

- **为什么不主推主赛道主题三**：① 100M 体积与跨平台两条硬约束，改造工作量大且偏离产品主线；② 开放选题中"AI 心理健康"会与大量泛 AI 项目混评，产品"本地优先 + 早期预警"的差异化容易被稀释。
- **揭榜第 9 题的代价**：① 名额更少（前 5 vs 前 10）；② 必须把"早期风险识别"而非"泛陪伴"讲成主线，需要在申报书与视频中刻意强化"识别 → 预警 → 干预"链路，弱化"生产力工具"等旁支。
- **双轨策略（可选）**：主投揭榜第 9 题；若时间允许，把主赛道主题三作为"工程挑战"备选——但前提是先完成 P2 的便携绿色版压缩（见 3.2），否则不建议分散精力。

## 二、评审标准差距分析（初评 / 复评 100 分）

### 2.1 选题价值（10 分）

**强项**
- 精准命中"大学生心理健康"这一高社会价值刚需，具备天然的社会意义与话题性。
- "本地优先 + 隐私优先"形成与云心理应用（Wysa、Woebot、简单心理等）的清晰差异化。
- 学术依据扎实：模型卡、风险方法论、外部人工验证报告三件套，可直接转化为选题可信度。

**短板**
- 同类产品多，需要把"本地优先 + 无感监测 + 早期预警"的组合讲成壁垒，否则易被归为"又一个聊天陪伴 app"。
- 尚未备好支撑数据（高校心理危机发生率、求助率低、咨询资源不足等），选题的"必要性"缺量化。

**针对性改进**
- 提炼一句话定位：**"不联网、更懂你的校园心理早筛陪伴助手"**。
- 申报书内置 2-3 个可引用数据（大学生抑郁检出率、求助率 < 10%、高校咨询师生比 1:5000 等），需 team-lead / 团队核实来源后使用。
- 明确合规定位：非医疗诊断、非替代咨询，而是"早筛 + 陪伴 + 转介"。

### 2.2 功能与实现（50 分，核心）

**强项**
- 功能完整度极高：陪伴（云/离线双模 + 记忆 + 主动）→ 监测（情感分析 / PANAS / 行为 / 风险评分 / C-SSRS）→ 干预（量表 / CBT / 呼吸 / 正念）→ 危机干预 → 预警 → 报告，形成闭环。
- 技术实现扎实且可稳定运行：ONNX 本地推理（97.6%）、AES-GCM 字段级加密、CSP 不放宽、DPAPI 密钥、PBKDF2 应用锁、打包版离线冒烟测试通过。
- 解决实际问题：预警 → 对话 → 干预链路是可直接演示的"问题到方案"闭环。

**短板（需重点补）**
1. **"97.6%"被追问风险**：这是**通用中文情感 4 分类**的测试集准确率，**不是**"心理风险识别"准确率。评委若问"97.6% 测的是什么"，当前无风险识别的量化口径，会失分。
2. **无反馈闭环（最大缺口）**：已有 `FeedbackService` + `feedbackLogs` 表，但只接了预警卡片"准不准"，**反馈只落库、不回灌**，模型/评分权重是"实验室固定值"而非"随用户个性化自校准"。
3. **风险评分是人工规则加权**（五信号源），缺乏可解释的个性化校准，也难以展示"自进化"这一 AI 记忆点。
4. **危机检测存在漏报空间**：关键词 + 模型的含蓄表达识别覆盖面有限，需诚实标注"可能存在漏报"并落到免责。

**针对性改进**
- **P0**：实现"反馈驱动自进化"闭环（见 3.1）——把 `feedbackLogs` 从"只读日志"升级为"本地校准数据源"，并补"知己度"感知层。这是把 50 分从"功能全"提升到"功能有灵魂"的关键。
- **P0**：为风险评分增加可解释性（"为什么是这个分：情绪 ↓、任务完成率 ↓、熬夜 ↑…"），并在视频中演示"用户纠正 → 评分/推荐变化"。
- **P1**：补一份"风险识别口径说明"（区分情感分类准确率 vs 风险分级逻辑），作为佐证材料。

### 2.3 用户体验与传播（20 分）

**强项**
- 界面完成度高：毛玻璃主题、深色、双语、新手引导、快捷键、快速记录。
- 关键链路操作清晰：预警横幅带"和知己聊聊"按钮直达对话。

**短板**
- **"它越来越懂我"无感知**：用户给了反馈却看不到任何变化（因反馈不回流），体验上"反馈是无效动作"。
- **缺少传播钩子**：无可分享的情绪报告卡片 / 海报，难以形成"可复制可推广"的视觉证据。
- **隐私价值不可见**：用户不知道"数据真的在本地"，差异化没有被可视化。
- 安装包 171MB 下载门槛高，无移动端。

**针对性改进**
- **P0**：反馈感知层（知己度 / 默契值 + 自进化时间线，见 3.1.4）。
- **P1**：隐私可视化说明（"数据不出本机"的一图流）、可分享周报卡片（导出 PNG）。
- **P2**：便携绿色版压缩、白标可配置（面向高校推广）。

### 2.4 创新与应用前景（20 分）

**强项**
- 本地优先的 ONNX 边缘推理（隐私 + 可离线）是真实的工程创新，非"套壳调 API"。
- 无感监测（打字行为、深夜活跃、学期节奏 ×1.5）与个性化干预推荐（规则 0.6 + 历史有效率 0.4）有差异化。

**短板**
- 创新点分散，缺一个"一句话记忆点"。
- "自进化"尚未实现，而它恰是最容易被评委记住、最具传播力的创新。
- "可复制可推广"未包装（如何落地到更多高校无方案）。

**针对性改进**
- 把核心创新收敛为一句：**"完全本地的、会随你的反馈自进化的心理早筛陪伴引擎"**。
- **P1**：准备"可复制推广方案"（高校心理健康中心合作、配置文件化白标、匿名聚合可选）。
- 用 `docs/` 三件套（模型卡 / 风险方法论 / 外部验证）作为"科学可信 + 可复制"的佐证。

## 三、新增功能建议

### 3.1 核心能力：反馈驱动的准确率自进化（P0，9/15 前必须）

> 现状：`FeedbackService.logFeedback()` 已能按 `sentiment / ai_response / recommendation / early_warning` 四类写入 `feedbackLogs`，但仅接预警卡片、只存不回流。本能力把"反馈收集"升级为"本地自进化闭环"。

#### 3.1.1 能力定义与目标

一句话定义：**用户以极低成本对"知己"的各类预测做出是非/偏差反馈，应用在本地据此校准个人化的分类阈值、风险权重与推荐偏好，并让用户明确感知"它越来越懂我"。**

- 目标 1（对齐 50 分）：把"静态准确率"升级为"随人进化的个性化准确率"，可演示、可量化。
- 目标 2（对齐 20 分）：把隐性反馈变成用户可感知的"默契"，强化情感连接与传播性。
- 目标 3（对齐隐私约束）：**全程本地，不引云、不跨用户聚合**（除非用户显式同意匿名汇总，且需评估 CSP）。

#### 3.1.2 反馈触点设计（用户在哪里反馈）

| # | 触点 | 预测对象 | 反馈内容 | 交互形态 | 优先级 |
|---|---|---|---|---|---|
| F1 | 日记 / 对话的情绪徽标旁 | ONNX 情感分类（negative/neutral/positive/crisis）与 sentimentScore | 纠正情绪标签（"其实是疲惫 / 生气 / 平静 / 开心…"） | 徽标旁小字"不对？"→ 展开情绪快选 | **P0** |
| F2 | 风险仪表盘 / 预警横幅 | 综合风险等级（五级 0-100） | 校准档位（"偏高 / 正好 / 偏低"） | 当前等级旁三个轻量小字按钮 | **P0** |
| F3 | 呼吸 / 正念 / 思维记录完成后 | 干预有效性（已有 moodBefore/After 隐式数据） | 显式有效性（"有帮助 / 一般 / 没帮助"） | 练习结束页底部一次点选 | **P0** |
| F4 | 报告 / 趋势图预测段 | 情绪趋势预测（direction + confidence） | 偏差确认（"预测相符 / 不符"） | 预测标注旁一次点选 | P1 |
| F5 | AI 对话回复气泡 | 回复质量（用于优化离线模板 / 上下文注入） | "有帮助 / 没帮助" | hover 气泡 👍/👎，仅本地 | P1 |

> 说明：F1/F2/F3 构成 9/15 前的自进化最小闭环（情感 / 风险 / 干预三条主线全覆盖）；F4/F5 为初评后的增量。

#### 3.1.3 交互设计原则（轻量、不打扰）

1. **零打断**：反馈永远内联、静默呈现，不弹窗、不拦截主流程；用户不点即视为"默认接受"，绝不强推。
2. **一次点击即完成**：默认动作 = 一次点选；仅在用户主动展开时才出现二级选项（如 F1 的情绪快选列表）。
3. **频率上限**：同类预测每天最多提示 1 次，避免骚扰（如风险等级校准每天最多 1 次）。
4. **危机场景禁用**：处于 critical/危机弹窗、或刚经历危机干预时，不呈现任何反馈入口——不让处于危机中的用户承担"校准"负担。
5. **可回滚**：设置页提供"重置个性化校准"，一键回到全局默认。
6. **诚实冷启动**：反馈样本不足（< N 次，建议 3-5 次）时，明确标注"样本还少，先按通用模型"，不伪造"已懂你"。

#### 3.1.4 "它越来越懂我"感知层

在 Dashboard 与 Emotion 页新增一个轻量模块——**「知己度」**（默契指数）：

- **总指数**：一个 0-100 的进度环，文案如"情绪识别默契度 92%，本周 +3%"。
- **分维度拆解**：情绪理解 / 风险判断 / 干预推荐 / 情绪预测四条，各自展示准确率与反馈次数。
- **自进化时间线**：近 30 天"你纠正 → 我调整"的事件流，例如"10/5 你说心情预测偏高 → 我调低了你的压力敏感度"。
- **置信度标注**：所有预测结果旁统一标注数据来源，如"基于你 14 天个人数据 + 你的 6 次反馈"。
- 目的：把"反馈有效"这件事可视化，让用户形成"我越用，它越懂我"的正向飞轮。

#### 3.1.5 自进化机制（产品层定义，技术由架构师设计）

所有校准在**本地个人校准层（Personal Calibration Layer）**完成，不训练云端模型、不跨用户：

- **情感分类（F1）**：用户纠正的文本 → 个人敏感词库 / 短语偏移（如用户把"累"纠正为疲惫而非难过，后续"累"类表达向疲惫倾斜）+ 阈值微调。输出仍走本地 ONNX + 个人偏移叠加。
- **风险等级（F2）**："偏高/偏低"反馈 → 对五信号源权重做 per-user 乘子微调（如用户长期反馈"偏高"则整体敏感度下调），校准个人风险基线。
- **干预推荐（F3）**：显式反馈合并进现有 `EffectivenessService` 有效率统计，动态调整"规则 0.6 + 有效率 0.4"的比例与个人 TOP 干预。
- **情绪预测（F4）**：偏差反馈修正趋势方向的置信度与阈值。
- **AI 回复（F5）**：仅用于本地优化离线模板与上下文注入策略，**不上传对话内容**。

原则：**可解释（每次调整给一句话理由）、可回滚（重置按钮）、冷启动诚实（样本不足退回默认）。**

#### 3.1.6 隐私与合规边界

- 反馈与校准数据仅存本地 `feedbackLogs`（或新增 `calibrationProfile`），走既有 AES-GCM 加密。
- 不引云、不匿名跨用户聚合（与 AGENTS.md"不引云"约束一致）。
- 危机场景不采集反馈；所有预测继续保留"非诊断"免责声明。

## 四、申报书 4×400 字段撰写要点

> 每段控制 380-400 字，围绕"陪伴 + 早期风险识别"主线，突出"本地自进化"记忆点。

**第 1 段 · 作品简介**
- 框架：一句定位 → 痛点 → 方案一句话 → 差异点 → 社会价值。
- 卖点素材：本地优先、隐私优先的校园心理早筛陪伴助手；把"陪伴、无感监测、早期预警、干预、危机转介"串成闭环；突出"不联网、会随你的反馈自进化"。
- 避免：堆功能清单、提"生产力工具"等旁支。

**第 2 段 · 主要功能与预期目标**
- 框架：三条主线各一句（① AI 对话陪伴：云/离线双模、跨会话记忆、危机联动；② 早期风险识别：情感分析 + 行为 + 风险评分 + 预警横幅；③ 干预闭环：量表/CBT/呼吸/正念 + 危机热线）；预期目标分"用户目标"（及时被提醒、被陪伴）与"系统目标"（早筛、转介）。
- 卖点素材：ONNX 本地推理 97.6% 情感分类、五信号源加权风险评分、预警→对话→干预链路、个性化干预推荐。
- 关键：把"预期目标"落到"提前发现风险、引导求助"，扣住题目"早期风险识别"。

**第 3 段 · 设计方案及技术实现**
- 框架：总体架构（Electron + React + Dexie + ONNX）→ 关键算法（两层情感分析、滑动窗口早期预警、风险评分、干预推荐）→ 隐私安全（AES-GCM、DPAPI、CSP、不引云）→ 数据闭环（反馈自进化）。
- 卖点素材：本地边缘推理而非调 API、字段级加密、42 单测 + 外部人工验证、模型卡 / 风险方法论。
- 关键：强调"技术实现的合理性与可稳定运行"（打包版 + 离线冒烟测试），并点出"反馈驱动的本地自校准"这一创新实现。

**第 4 段 · 创新及应用前景**

- 卖点素材：隐私优先的差异化、无感监测（打字/深夜/学期节奏）、个性化自进化、白标可配置。
