## 1. 原始需求复述

参赛作品 FriendOS 是一款面向年轻人的本地 AI 心理健康陪伴与早期风险识别桌面助手。当前前端功能完整度约 93%，但**多项"AI 能力"未真正跑通或名不副实**，与比赛「功能与实现 50 分 + 用户体验与传播 20 分 + 创新与应用前景 20 分 + 选题价值 10 分」的评分要求存在关键差距，且在决赛（**统一使用大赛设备与网络，可能无网、无 API Key**）存在演示翻车风险。本 PRD 聚焦"以 1.5 个月为约束、以决赛现场演示与答辩不翻车 + 评分项最大化"为目标，产出差距分析与需求清单。

## 2. 产品定义

### 2.1 产品定位（针对主题9）

> **一句话定位**：一款数据不出本机、7×24 可用的 AI 心理健康陪伴与早期风险识别助手——用可解释的 AI 情感理解与多源信号风险预警，陪伴用户每一天，并在危机到来前"提前一步"发出提醒。

对比赛的三点价值主张（对应选题价值 + 创新前景）：

1. **隐私优先（本地优先）**：全部数据（日记、情绪、量表、对话）加密存于本机 IndexedDB，AI 情感识别本地 ONNX 推理，云 API 仅作可选增强。契合"心理健康数据敏感"的社会痛点。
2. **科学可信（早期风险识别）**：情感分类基于真实训练的 ONNX 模型（crisis 召回 98.87%），风险预警基于多信号（情绪/行为/量表/聊天/日记）加权 + 趋势统计，并以模型卡、评估报告、可解释性展示支撑"科学依据"。
3. **全流程陪伴闭环**：记录（日记/情绪/量表）→ 理解（AI 共情对话）→ 识别（情感分类/风险评分）→ 预警（绿/黄/橙/红）→ 干预（报告/建议/治疗资源）。

### 2.2 产品目标（3 个正交目标）

| 编号 | 目标 | 衡量方式 | 对应评分项 |
|---|---|---|---|
| G1 | **现场可演示**：全功能在无网、无 API Key 的决赛设备上 5 分钟内可完整演示、不报错、不穿帮 | 断网 + 删 Key 冒烟演示通过率 100% | 功能与实现50 / 现场演示15 |
| G2 | **科学可信**：风险预测与情感识别的"科学依据"可被答辩 3 分钟讲清楚、经得起追问 | 交付模型卡 + 评估报告 + 外部验证报告，答辩话术演练通过 | 创新性25 / 答辩表现10 |
| G3 | **体验可传播**：UI/UX 完成度、演示叙事达到"评委愿意转发"的水平 | 5 分钟演示视频叙事完整、UI 无半成品感 | 用户体验与传播20 |

### 2.3 核心用户故事

1. 作为一名**心情低落的大学生**，我想用自然语言和 AI 助手倾诉，让它先共情、再追问，这样我即使在深夜也有人陪伴（且隐私不出本机）。
2. 作为一名**长期记录情绪/日记的用户**，我想看到我的情绪趋势和风险等级变化，这样我能感知自己是否正在变好或变差。
3. 作为一位**关注学生心理的辅导员/咨询师**，我想看到可解释的风险预警（为什么、基于哪些信号），这样我能决定是否需要介入，而不是收到一个"黑盒分数"。
4. 作为**决赛评委**，我想在无网设备上 5 分钟内看到从"倾诉→识别→预警→报告"的完整闭环，并能在答辩中验证其科学依据与隐私承诺。
5. 作为**参赛团队成员**，我想在 1.5 个月内用最小成本把"名不副实的 AI"变成"能自证的 AI"，避免演示翻车与答辩被质疑。

## 3. 差距分析表（现状 → 比赛要求 → 差距 → 优先级）

> 优先级定义：**P0 = 必须修复**（不修则演示翻车 / 评分硬伤 / 答辩被击穿）；**P1 = 必须新增**（评分项重要缺口）；**P2 = 强烈建议**（加分项，时间允许再做）。

| # | 维度 | 现状（已验证事实） | 比赛要求 / 期望 | 差距 | 优先级 | 影响评分项 |
|---|---|---|---|---|---|---|
| D1 | 本地 AI 对话 | 对话依赖云 API（通义/DeepSeek），无 Key/断网时降级到**模板引擎**（共情+追问，10+条/分支）；文档宣称"完全离线 Qwen3.5-0.8B GGUF"，但 `pc/models/` 下**只有 sentiment，GGUF 不存在**，local-model IPC 已移除 | 决赛统一设备+网络，可能无网无 Key；AI 对话必须可演示 | **离线对话名不副实，现场演示只能走模板**，且自由问答易穿帮 | **P0** | 功能与实现50 / 现场演示15 |
| D2 | "AI 预测"名不副实 | 风险评分=5 信号加权规则；早期预警=线性回归+异常分；情绪预测=移动平均+斜率——**全部为启发式规则/统计，无真 ML 预测**，但对外表述易被理解为"AI 预测" | 主题9 核心是"早期风险识别"，答辩要能自证 | 叙事风险：答辩说"AI 预测"会被评委追问"模型在哪、训练数据是什么" | **P0** | 创新性25 / 答辩表现10 |
| D3 | 科学依据薄弱 | 训练标注为**关键词弱标注**（非人工）；测试集与训练集同分布；**无模型卡/评估报告/外部验证/可解释性说明** | 心理健康产品必须有数据来源、指标、局限性的严谨说明（评委/伦理敏感） | 指标虚高存疑；"预测有科学依据"站不住脚 | **P0** | 创新性25 / 答辩表现10 / 选题价值10 |
| D4 | 风险可解释性 | RiskDashboardPage 有评分/雷达/信号源，但**未解释"为什么是这个分/这个预警等级"**，无"信号→证据→结论"链路展示 | 早期风险识别应可解释、可信任 | 用户/评委看不到判断依据 | **P0** | 功能与实现50 / 实用性25 |
| D5 | 无网演示准备 | 无演示模式/演示数据注入/启动自检；决赛设备环境未知 | 现场 5 分钟演示必须稳定 | 无预置数据、无降级可视化，演示依赖运气 | **P0** | 现场演示15 |
| D6 | 量表完整性 | PHQ-9、GAD-7 已实现；**PSS-10 未实现**；C-SSRS 分级参考 | 心理评估功能完整、有依据 | PSS-10（压力感知）缺口 | **P1** | 功能与实现50 |
| D7 | 用户体验与传播 | 前端约 93% 完成，但未按"演示叙事"打磨；情绪可视化、新手引导、隐私可见化不足 | 用户体验与传播 20 分 | UI/UX 与传播素材需专项打磨 | **P1** | 用户体验与传播20 |
| D8 | 申报/视频材料 | 未形成作品申报书素材、5 分钟演示视频脚本 | 提交材料：申报书 PDF + 视频 ≤5min + 可执行程序 | 材料缺叙事主线 | **P1** | 初评整体 |
| D9 | 创新加分 | 有风险看板、报告 AI、记忆系统，但缺"个性化基线/真预测/语音/可视化叙事"等亮点 | 创新与应用前景 20 分 | 创新点不突出 | **P2** | 创新与应用前景20 |
| D10 | 情感模型本身 | ONNX 4 分类已跑通：accuracy 97.57%、crisis recall 98.87%（同分布测试集 6050 条） | 真 ML 能力（这是本项目最硬的牌） | 模型可用，但**缺文档化包装**（模型卡/外部验证） | P0（文档化） | 功能与实现50 |

## 4. 需求池

### 4.1 P0 · 必须修复（不修则演示翻车 / 答辩被击穿）

| 编号 | 需求 | 说明 | 验收标准（Definition of Done） |
|---|---|---|---|
| P0-1 | **本地对话兜底方案落地**（三选一或组合） | A. 接入真本地小模型（ONNX/GGUF 0.5~1B，量化后 ≤300MB，CPU 推理 <3s）；B. 升级模板引擎为"情感感知多轮对话"（用已跑通的 ONNX 情感分类驱动回复分支 + 上下文摘要 + 状态机）；C. 预置高质量演示对话脚本（Demo Script）。**建议 B 为主 + C 保底，A 做 2 周技术验证、能跑通则上** | 断网 + 删除 API Key 环境下：AI 助手 5 分钟完整演示 0 报错；连续对话 ≥6 轮上下文连贯、情感匹配；不出现明显机械感穿帮 |
| P0-2 | **演示模式（Demo Mode）+ 启动自检** | 一键注入 30 天演示数据（日记/情绪/任务/量表/风险事件）；启动自检面板显示：联网状态 / 模型状态 / API Key 状态 / 降级路径，状态一目了然；演示数据可一键清理，不污染真实数据 | 点击"演示模式"后 30 秒内所有页面有数据可展示；自检面板在断网时明确提示"离线模式-模板对话已就绪"；退出演示模式数据完整清理 |
| P0-3 | **风险预测科学依据补强（叙事重构 + 文档）** | 对外表述统一为"**基于多信号的可解释风险评估 + 统计早期预警 + ML 情感/危机识别**"，不再笼统称"AI 预测"；明确"统计预测≠诊断"；交付《风险预警方法说明》（5 信号权重依据、3 天窗口特征、异常分定义、阈值来源） | 交付 `docs/risk_methodology.md`；答辩 3 分钟可讲清"哪些是真 ML、哪些是统计方法、各自依据"；评委追问"预测依据"时有完整话术 |
| P0-4 | **情感模型模型卡 + 评估报告** | 模型卡：用途/训练数据来源（3 数据集+增强）/标注方式（如实写关键词弱标注）/指标（同分布测试集 accuracy 97.57%、crisis recall 98.87%）/局限性/预期用途与禁止用途；评估报告：混淆矩阵、类别指标、错误案例分析、与规则基线对比 | 交付 `docs/model_card.md` + `docs/eval_report.md`；数据来源可追溯（每个数据集出处/许可/处理流水线） |
| P0-5 | **外部验证（人工抽检）** | 从测试集外抽 100~200 条，由 2~3 人盲评情感标签，计算与模型一致率；结果写入评估报告（如实呈现，含不一致示例） | 交付 `docs/external_validation.md`；一致率数据 + 分析结论 |
| P0-6 | **风险可解释性展示** | 风险看板增加"证据链"视图：当前风险分 → 各信号贡献（情绪 0.30/行为 0.25/评估 0.25/聊天 0.10/日记 0.10）→ 触发预警的具体依据 → 建议动作；预警等级（绿/黄/橙/红）给出规则解释 | 在 RiskDashboardPage 任意预警卡片可下钻到"证据链"；无"黑盒分数"观感 |
| P0-7 | **伦理与安全红线** | 危机文本（crisis 分类）触发：明确提示语（"我不能替代专业医疗，请立即联系…"）+ 干预资源页（心理援助热线等）；申报书中体现伦理合规 | 危机文本演示路径可走通；提示语与资源页存在且可在演示中展示 |

### 4.2 P1 · 必须新增（评分项重要缺口）

| 编号 | 需求 | 说明 | 验收标准 |
|---|---|---|---|

### 4.3 P2 · 强烈建议（创新加分项，时间允许再做）

| P2-5 | **数据导出/咨询师视图** | 用户可导出脱敏报告（供咨询师参考），体现应用前景 | 报告可导出 PDF/Markdown（脱敏） |

## 5. 需求优先级总览与时间建议（1.5 个月）

```
第1周   P0-1 对话兜底方案选型 + P0-2 演示模式/自检骨架  （先解决"会不会翻车"）
第2周   P0-3/P0-4 方法说明 + 模型卡/评估报告初稿 + P0-6 证据链UI
第3周   P0-1 方案B落地（情感感知模板）+ P0-5 外部验证抽检
第4周   P0-2 完善 + P1-1 PSS-10 + P1-2 UI/UX 第一批
第5周   P1-2 第二批 + P1-3 视频脚本 + P1-4 打包验证
第6周   全量冒烟 + 申报书/视频成稿 + 答辩话术演练（留 3~5 天缓冲）
穿插    P2 项仅做"1 个最能讲故事的"（建议 P2-1 个性化基线 或 P2-2 真预测）
```

> 风险提示：**不要同时做多个 P2**。P2 只选一个与"早期风险识别"叙事最契合的（推荐 P2-2 或 P2-1），把精力集中在 P0/P1 的完成度上——决赛 50% 权重在"功能与实现"，稳定完整远胜亮点堆砌。

## 6. 待确认问题（需用户/主理人拍板）

1. **决赛设备**：是否确认统一提供设备、不允许自带？现场设备性能（CPU/内存/是否 Windows）未知——这直接决定 P0-1 能否上真本地模型（A 方案）。若可自带设备，建议带高性能笔记本，A 方案可行性大增。
2. **对话方案取舍**：是否接受"本地情感感知模板引擎 + 云增强（可选）"作为最终对话方案？还是必须在本地上真小模型（接受打包体积与推理速度风险）？
3. **训练数据合规**：3 个训练数据集（SoulChat2.0 等）的开源许可是否允许在申报书中如实公开来源与用途？（影响 P0-4 数据追溯写法）
4. **人工标注资源**：是否有 2~3 人可在 1 周内完成 100~200 条外部验证盲评？（无人的话，P0-5 需降级为"作者自评 + 抽样展示"）
5. **P2 取舍**：时间只够做一个加分项，团队更倾向 P2-1（个性化基线）还是 P2-2（真 ML 预测）？是否接受砍掉语音（P2-3）？
6. **演示视频形式**：录屏为主还是动画/混合？（影响 P1-3 脚本与 UI 打磨优先级）
7. **真实用户数据**：目前是否有真实/模拟用户数据可用于演示模式与个性化基线？（没有则 P0-2 需生成合成演示数据）
8. **申报书署名与指导老师**：是否已有指导老师与学院背书信息？（影响选题价值 10 分的呈现）

## 7. 一句话结论（给主理人/架构师）
