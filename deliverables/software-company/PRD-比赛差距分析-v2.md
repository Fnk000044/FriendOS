## 1. 原始需求复述

FriendOS 是一款本地优先、隐私优先的桌面心理健康应用，已具备日记/任务/习惯/情绪记录、PHQ-9/GAD-7/PSS-10 评估、风险评分、AI 对话等基础能力。现状存在「名不副实的 AI」硬伤：对话离线降级引擎机械、风险/情绪预测均为统计方法但未如实说明、无科学文档、演示数据不可复现。本次目标：在决赛（**大赛设备，可能无网、无 API Key**）现场演示不穿帮、答辩可自证科学依据、评分项最大化。

> 已拍板方向（v2 相对 v1 的关键变化）：对话方案**不做本地真小模型**，采用「情感感知模板引擎 + ONNX 4 分类情感驱动 + 会话状态机」；有云 Key 时自动增强。

## 2. 产品定义

### 2.1 产品目标（3 个正交目标）

| 编号 | 目标 | 衡量方式 | 对应评分项 |
|---|---|---|---|
| G1 | **现场可演示（保命）**：全功能在无网、无 API Key 决赛设备上 5 分钟完整演示，0 报错、0 穿帮 | 断网 + 删 Key 冒烟演示通过率 100%；离线对话 ≥6 轮不重复、情感匹配 | 功能与实现50 / 现场演示15 |
| G2 | **科学可信（答辩）**：风险识别与情感识别的「科学依据」文档化，3 分钟答辩讲得清、经得起追问 | 交付方法说明 + 模型卡 + 评估报告 + 外部验证报告骨架；对外统一表述落地 | 创新性25 / 答辩表现10 |
| G3 | **体验可传播（加分）**：情绪可视化叙事化 + 30 秒演示路径，让评委快速 get 到亮点 | 30 秒演示路径可在打包版走通；录屏无半成品/空状态 | 用户体验与传播20 |

### 2.2 核心用户故事

1. 作为一名**深夜心情低落的大学生**，我想在断网状态下用自然语言向 AI 倾诉，让它先共情、再追问，这样我在任何时刻都有人陪伴（且隐私不出本机）。
2. 作为一名**长期记录情绪/日记的用户**，我想看到情绪热力图、趋势与分布，这样我能直观感知自己是否在变好或变差。
3. 作为一位**关注学生心理的辅导员/咨询师**，我想看到风险分数的「证据链」（为什么是这个分、基于哪些信号），这样我能判断是否需要介入，而不是收到一个黑盒分数。
4. 作为**决赛评委**，我想在无网设备上 30 秒看到从「倾诉→情感识别→风险看板→证据链→危机干预」的完整闭环，并能在答辩中验证其科学依据与伦理合规。
5. 作为**参赛团队**，我想让演示数据 30 天确定性可注入/清理、启动自检一目了然，这样现场演示不依赖运气、不翻车。

## 3. 技术规范

### 3.1 需求池（P0 保命 / P1 加分 / P2 简化版加分）

> 优先级定义：**P0 = 必须交付**（不交付则演示穿帮 / 答辩被击穿 / 评分硬伤）；**P1 = 评分项重要加分**；**P2 = 简化版加分项**（时间允许再做，且如实标注为统计学习）。
> 说明：v1 中的 P1-1（PSS-10）已在现状中实现，v2 不再列入需求池，编号从 P1-2 起，与主理人指令一致。

#### P0 · 保命（7 条）

| 编号 | 需求 | 说明 | 验收标准（DoD） |
|---|---|---|---|
| P0-1 | **离线多轮对话不穿帮**（已拍板方案） | 情感感知模板引擎 + ONNX 4 分类情感驱动 + 会话状态机；不做本地真小模型；有云 Key 时自动增强（走通义/DeepSeek SSE）。状态机覆盖：greeting → empathize(共情) → follow-up(追问) → crisis(固定回复) → closing；同一分支模板去重 | 断网 + 删 Key：连续对话 ≥6 轮情感匹配、上下文连贯、无重复模板；危机文本触发固定回复；云端可用时自动增强且 UI 标识来源 |
| P0-2 | **演示数据 30 天确定性可注入/清理 + 启动自检面板** | 30 天确定性故事线（固定种子可复现：日记/情绪/任务/量表/风险事件），一键注入、一键清理，不污染真实数据；启动自检面板四状态：联网 / 模型 / API Key / 降级路径 | 注入后 30 秒内所有页面有数据可展示；清理后数据完整还原；自检面板断网时明确提示「离线模式-模板对话已就绪」 |
| P0-3 | **科学文档（方法说明）** | 交付 `docs/risk_methodology.md`：哪些是真 ML（ONNX 情感/危机识别）、哪些是统计方法（5 信号加权、线性回归斜率、异常分）、各阈值来源（信号权重 0.30/0.25/0.25/0.10/0.10、3 天窗口、预警绿/黄/橙/红、风险 5 级切分点） | 对外统一表述落地为「**多信号可解释风险评估 + 统计早期预警 + ML 情感/危机识别**」，禁止笼统说「AI 预测」；答辩可讲清「哪些真 ML、哪些统计、各自依据」 |
| P0-4 | **模型卡 + 评估报告** | 交付 `docs/model_card.md` + `docs/eval_report.md`：模型用途/训练数据来源（3 数据集+增强）/标注方式（如实写关键词弱标注）/指标（同分布测试集 6050 条 accuracy 97.57%、crisis recall 98.87%）/混淆矩阵/错误案例分析/局限性/预期与禁止用途 | 数据来源可追溯（每个数据集出处/许可/处理流水线）；指标如实呈现，不夸大 |
| P0-5 | **外部验证报告骨架 + 脚本** | 分层抽样 120 条（按 4 类别分层）+ 盲评 CSV 模板 + 一致率计算脚本；2~3 人盲评后如实填入结果（含不一致示例） | 脚本可复现抽样与 CSV 生成；报告骨架含抽样方法/盲评流程/一致率公式；人工结果可后补、如实呈现 |
| P0-6 | **风险分数证据链** | 风险看板增加「证据链」视图：当前分数 → 各信号贡献（情绪 0.30/行为 0.25/评估 0.25/聊天 0.10/日记 0.10）→ 触发预警的具体依据 → 建议动作 → 免责声明 | 任意预警卡片可下钻到证据链；无「黑盒分数」观感 |
| P0-7 | **伦理红线** | 危机文本触发：提示「我不能替代专业医疗，请立即联系…」+ 干预资源页展示 **12356（全国统一心理援助热线）** 与 **400-161-9995** + 危机固定回复 + 免责声明 | 危机演示路径可走通；话术与热线在 UI 可见；申报书中体现伦理合规 |

### 3.2 UI 设计稿（关键页面文字描述）

**① 启动自检面板（新增）**
- 入口：应用启动后首屏弹出（可关闭），设置页可随时重新打开
- 布局：四个状态卡片（联网状态 / 情感模型 / API Key / 降级路径），每卡状态灯（绿=就绪、黄=降级可用、灰=不可用）+ 一句话说明；底部「演示模式」主按钮 + 「注入 30 天演示数据 / 清理演示数据」两个次级按钮
- 断网示例文案：`离线模式-模板对话已就绪（情感感知增强中）`

**② 聊天页（改造 ChatPage）**
- 消息气泡：本地回复带「本地」徽标，云增强回复带「云端」徽标，来源透明
- 情感感知：输入后内部跑 ONNX 4 分类，负面/危机回复走共情/危机分支；危机固定回复用警示色气泡 + 热线提示
- 会话连贯：状态机驱动的追问引用上文关键词（如「你刚才提到…」），模板去重，≥6 轮不穿帮

**③ 风险看板（改造 RiskDashboardPage）**
- 顶部：风险评分卡 + 早期预警卡（绿/黄/橙/红）
- 预警卡可点击 → 展开「证据链」抽屉（P0-6）：当前分数 → 5 信号贡献条（带数值）→ 触发预警的具体依据（如「连续 3 天负面情绪占比 >60%」）→ 建议动作 → 免责声明

**④ 情绪可视化（新增/增强）**
- 月历热力图：30 天每日情绪色块（负=蓝/危机=红/中=灰/正=黄），点击某日看当日记录
- 趋势 Sparkline：7/30 天情绪走势；分布图：四分类占比

**⑤ 危机干预资源页（新增）**
- 固定话术卡：「我不能替代专业医疗。如果你处于危险中，请立即联系专业帮助」
- 热线卡：12356（全国统一心理援助热线）+ 400-161-9995
- 免责声明常驻底部

### 3.3 待确认问题

1. **演示数据人设**：30 天故事线的「主角」设定（如大四学生就业压力→情绪波动→量表→恢复）是否由产品侧给出最终版？合成数据需可讲、可复现、合规。
2. **外部验证人工资源**：是否有 2~3 人可在截止前完成 120 条盲评？无则 P0-5 以「骨架 + 脚本 + 作者自评」交付，一致率如实标注。
3. **30 秒路径与 5 分钟视频**：是否共用同一故事线？（建议共用，避免两套叙事）
4. **打包验证环境**：QA 是否有干净离线 Windows 虚拟机/机器做 P1-4 冒烟？（无则用本机断网模拟，如实记录差异）
5. **P2 取舍**：P2-1 与 P2-2 都做简化版，还是只选其一？（推荐至少做 P2-2，因与「早期风险预测」主题最契合）
6. **数据合规**：3 个训练数据集（SoulChat2.0 等）的开源许可是否允许在申报书中如实公开来源与用途？（影响 P0-4 数据追溯写法）
7. **申报书/视频材料归属**：本 PRD 聚焦产品与工程，申报书 PDF 与 5 分钟视频由谁产出？（建议另立任务，产品侧提供脚本与素材）

## 4. 给架构师的一句话

> **P0 全部围绕「决赛不翻车 + 答辩能自证」：P0-1 情感感知模板引擎 + 会话状态机（不做本地大模型）、P0-2 演示数据与自检、P0-3~P0-5 科学文档三件套、P0-6 证据链、P0-7 伦理红线；P1 做叙事与打包验证；P2 只做简化版统计预测并如实标注。核心心法：少说「AI 预测」，把已有的真 ML（情感/危机识别）与严谨统计方法讲扎实。**
