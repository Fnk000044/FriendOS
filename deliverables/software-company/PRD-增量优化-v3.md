## 4. UI 设计要点

### 4.1 任务日历标记方式（#4）
- 现状：日期旁小彩点不明显。
- 方案（推荐）：**日期格右上角 8×8px 圆角方框角标**（颜色语义：灰=有任务未完成、绿=全部完成、橙=有预警/逾期、蓝=有情绪记录）；角标置于日期数字右上，与数字不重叠（4px 间距）。
- 备选：日期数字下方 4px 全宽色条（适合格子较窄的月视图）。
- 补充：悬停日期显示 tooltip（如"6 月 12 日 · 3 个任务 · 1 个已完成"）；角标颜色与任务/情绪状态联动。

### 4.2 任务打勾动效（#5）
- 点击圆圈：圆圈 120ms 内填充为品牌色 → 中间淡入白色对勾（scale 0.6→1，200ms ease-out）→ 任务文字 200ms 渐变划线 + 颜色变淡。
- 取消勾选：对称反向动画。
- 约束：列表项高度固定，动效不改变布局（overflow 不跳动）；用 CSS transform/opacity，避免重排。

### 4.3 聊天输入框焦点修复（#1）
- 根因定位建议：提交后父组件 state 变化触发输入框重挂载/失焦。
- 方案：① 输入框组件 `React.memo` + 提交回调不替换组件 key；② 提交后不清空导致失焦的受控状态，用 `ref.current.focus()` 兜底恢复；③ 输入框 `onBlur` 不触发全局 state 重置；④ 输入框 DOM 结构稳定（不随消息数量重建）。
- 验收：连续发送 5 条消息，输入框始终可点击、光标正常。

### 4.4 证据链弹层层级（#16）
- 统一 z-index 规范：页面内容 ≤ z-40；**弹层遮罩 z-50、弹层内容 z-60**（Tailwind 体系）；所有弹层（证据链/危机干预/详情）遵守同一套。
- 排查父级 stacking context：若弹层父节点含 `transform/opacity/filter/overflow` 会创建新层叠上下文，需将弹层提升为页面级 portal（`createPortal` 到 body）。
- 验收：证据链弹层打开时覆盖全部卡片、关闭无闪烁；与 P1-5 取消闪黑联动验证。

### 4.5 风险时间线图例（#20）
- 图结构：X 轴=日期（7/30 天）；Y 轴=风险分数（0-100，网格线 + 刻度标签）。
- 元素：每日风险分数点 + 连线；**红色虚线=风险阈值线**（如 60 分，图例标注"预警阈值"）；点颜色=风险等级（绿/黄/橙/红）。
- 图例区（图右上或下方）：「绿=低 · 黄=中 · 橙=高 · 红=危急 · 红色虚线=预警阈值 · 圆点=每日风险评分」。
- 交互：悬停点显示 tooltip（日期 + 分数 + 主要信号）；底部 1-2 句自动解读（如"最近 7 天风险分数整体平稳，未触发预警"）。

### 4.6 关于页结构（#31）
- 位置：侧边栏与"设置/习惯"同级新增"关于"。
- 内容两段式：
  1. **隐私与数据安全**：数据只在本机（本地存储 + 加密说明）、数据导出/清除入口、存储位置查看；
  2. **关于知己**：产品名称与版本号、一句话简介、技术栈简述（本地优先）、伦理声明（"本应用不替代专业医疗诊断"）、心理援助热线（12356 / 400-161-9995）、致谢。
- 布局：左侧导航（设置 / 习惯 / 关于），右侧内容区；与现有侧边栏样式统一。

### 4.7 记忆板块定位（#25）
- 定位文案（示例）："记忆会自动收录你在对话、日记和任务中的关键信息，帮你快速回顾重要内容。"
- 空态引导：居中插图/图标 + 定位说明 + 两个引导按钮（"去写一篇日记" / "去和知己聊聊"）；提示"当你有记录后，这里会展示自动提取的要点"。
- 有数据态：卡片列表（时间 + 来源类型 + 摘要 + 点击回看上下文）。
- 若"提取无内容"是技术 bug，另走 P0 修复；定位与空态属于产品层。

### 4.8 其他 UI 细节
- **输入框轮廓（#7）**：统一 border（如 `border-gray-300 dark:border-gray-600`）+ focus 高亮（品牌色 ring）；与背景形成对比，暗色模式同样可辨。
- **综合风险指数背景（#17）**：指数卡片使用不透明背景（白/深色卡片 + 阴影），不依赖图表底纹。
- **图表加载动画（#12）**：图表容器渲染前显示 spinner 或骨架屏（≤500ms）；数据就绪后淡入。
- **自检与设置合并（#30）**：设置页内嵌"自检"区块（可折叠），保留"重新自检"按钮；独立弹窗流程移除。
- **二级菜单居中（#33）**：弹层/菜单的定位基准改为右侧主内容区（相对主区容器 `absolute`/`fixed` + 主区坐标），不再相对整个 BrowserWindow 居中。

## 5. 命名统一规范建议

> 原则：**规则引擎/统计方法的结果不叫"AI"**；只有真实 ML（ONNX 情感/危机识别）与云端 LLM 可保留技术性表述；产品内统一用品牌词"知己"。

| 现表述 | 建议表述 | 原因 |
|---|---|---|
| AI 助理 / AI 对话 | **知己助理**（英文：Zhiyou Assistant） | 产品品牌统一 |
| ai分析报告 / AI 分析报告 | **心理分析报告**（英文：Mental Health Analysis Report） | 规则模板生成，非 AI |
| 让 AI 分析本周心理健康数据 | **生成本周心理健康分析**（英文：Generate Weekly Analysis） | 去除"AI"字眼 |
| AI 预测 / AI 分析 | **趋势预测**（标注"基于统计方法"） | 如实表述 |
| 规则引擎结果 | **本地规则分析**（英文：Local Rule-based Analysis） | 不叫 AI |
| 云端 LLM 回复 | **云端模型（DeepSeek）** | 明确来源而非笼统"AI" |
| 情感识别 | 保留"情感识别（ML 模型）" | 真实 ML，可保留并如实标注 |
| 建议/建议库 | 保留"建议" | 无 AI 字眼，无需改 |

- 落实方式：以 `pc/src/i18n/translations.ts` 为唯一文案源，zh-CN 与 en 成对更新；页面硬编码文案一并清理。
