## 1. 安全性与隐私评估

### 1.1 数据存储安全

| 项目 | 状态 | 风险等级 | 说明 |
|------|------|----------|------|
| 数据库加密 | ❌ 未加密 | 高 | IndexedDB (Dexie) 数据以明文存储在本地，无加密 |
| API Key 存储 | ⚠️ 部分加密 | 中 | Electron 侧使用 `safeStorage` 加密，但前端 Zustand 将 API Key 明文存入 localStorage |
| 密码哈希 | ✅ 已实现 | 低 | 应用锁使用 SHA-256 + 盐值哈希 |
| 同步令牌 | ⚠️ 无过期 | 中 | 同步 Token 为 UUID，无过期机制，长期有效 |
| 本地模型路径 | ⚠️ 硬编码 | 低 | 默认路径 `E:\FriendOS\models` 包含用户系统信息 |

### 1.2 网络安全

| 项目 | 状态 | 风险等级 | 说明 |
|------|------|----------|------|
| HTTPS 通信 | ✅ 已实现 | 低 | API 调用使用 HTTPS |
| Prompt 注入防护 | ✅ 已实现 | 低 | `sanitizeUserInput` 过滤注入模式 |
| 同步服务器认证 | ✅ Token 认证 | 低 | 使用随机 UUID Token |
| `open-external` 验证 | ❌ 无验证 | 高 | 可打开任意路径/可执行文件，无白名单 |
| CORS 策略 | ⚠️ 宽松 | 中 | 同步服务器设置 `Access-Control-Allow-Origin: *` |

### 1.3 隐私风险

| 项目 | 风险 | 说明 |
|------|------|------|
| 日记内容 | 高 | 明文存储在本地 IndexedDB，无加密 |
| 情感分析数据 | 中 | 情感记录、健康档案明文存储 |
| AI 对话历史 | 中 | 对话摘要存储在数据库，可能被注入到后续提示词 |
| 云端 API 传输 | 中 | 使用在线模式时，用户数据发送到 DeepSeek 服务器 |
| 使用统计 | 低 | 无遥测/分析代码 |

### 1.4 安全问题汇总与修复建议

| 优先级 | 问题 | 修复建议 |
|--------|------|----------|
| **P0** | API Key 明文存入 localStorage | 移除 zustand persist 中的 apiKey，仅通过 Electron IPC 加密存储 |
| **P0** | `open-external` 无路径验证 | 添加路径白名单或协议验证 |
| **P1** | IndexedDB 数据未加密 | 考虑使用 SQLCipher 或 AES 加密敏感字段 |
| **P1** | 同步 Token 无过期 | 添加 Token 过期时间（建议 10 分钟） |
| **P2** | CORS 策略过宽 | 限制为特定 IP 段 |
| **P2** | 对话摘要未消毒 | 存储前调用 `sanitizeUserInput` |

### 2.3 玻璃拟态（Glassmorphism）设计评估

**当前风格：** Tailwind 默认实色背景 + 阴影卡片  
**目标风格：** 玻璃拟态（毛玻璃、透明度、背景模糊）

#### 效果预估

| 方面 | 评估 |
|------|------|
| 视觉层次 | 显著提升，卡片与背景分离更明显 |
| 现代感 | 大幅提升，符合 2024-2026 设计趋势 |
| 可读性 | 需要注意，浅色模式下透明度不宜过高 |
| 性能影响 | `backdrop-filter: blur()` 在 Electron 中性能良好 |
| 深色模式 | 天然适配，效果更佳 |

#### 工作量评估

| 改动项 | 文件数 | 工作量 |
|--------|--------|--------|
| 全局背景渐变 + 装饰色块 | 2 | 0.5h |
| 通用组件（Card, Modal, Button） | 5 | 2h |
| 侧边栏 + 顶栏 | 3 | 1h |
| 各页面卡片替换 | 12 | 3h |
| 深色模式适配 | 1 | 1h |
| 输入框 + 选择器 | 4 | 1h |
| **总计** | **~25 文件** | **约 1-2 天** |

#### 推荐色彩方案


### 3.3 竞争优势分析

**FriendOS 独特优势：**

1. **桌面原生应用** — 市场上几乎无竞品是桌面原生（大多数是移动端）
2. **功能最全面** — 唯一一款同时具备 AI 对话 + 日记 + 情绪追踪 + CBT + 呼吸 + 习惯的应用
3. **完全离线** — 本地 Qwen3 模型，无需联网，数据不出设备
4. **免费开源** — 无订阅费，无广告
5. **数据自主** — 用户完全控制自己的数据

**FriendOS 劣势：**

1. **无移动端** — 大多数竞品是移动优先
2. **无专业治疗师** — BetterHelp/Talkspace 提供真人治疗
3. **AI 质量** — 0.6B 模型能力有限，不如云端大模型
4. **临床验证** — Woebot 有斯坦福临床验证，FriendOS 无
5. **用户规模** — 竞品有数百万用户，FriendOS 是新项目

### 3.4 差异化定位建议

```
FriendOS = 离线版 Woebot + 本地版 Daylio + 免费版 Moodfit
```

**目标用户：**
- 注重隐私、不愿将心理数据上传云端的用户
- 需要桌面端长时间使用的用户（学生、办公族）
- 预算有限、不愿支付订阅费的用户

## 4. 科学性与准确率评估

### 4.1 情感分析准确率

| 测试场景 | 旧版本 | 新版本（三层分析） |
|----------|--------|-------------------|
| "不想活了，想跳楼了" | ❌ 漏报（否定词 bug） | ✅ 正确检测为 high |
| "活不下去了" | ❌ 漏报 | ✅ 正确检测 |
| "我在看跳楼视频" | ❌ 误报 | ✅ Qwen3 判断为 low |
| "今天心情不错" | ✅ 正确 | ✅ 正确 |
| "好难过好焦虑" | ✅ 正确 | ✅ 正确 |
| "小说里的人想死" | ❌ 误报 | ✅ Qwen3 判断为 low |

**准确率评估：**
- 关键词层：召回率高（宁可误报不漏报），精确率低
- ONNX 层：情感分类准确率约 80-85%（BERT 模型）
- Qwen3 层：语义理解准确率约 70-80%（0.6B 小模型限制）

### 4.4 潜在错检/漏检风险

| 风险 | 场景 | 影响 | 缓解措施 |
|------|------|------|----------|
| **误报** | 用户引用歌词/小说 | 中 | Qwen3 语义判断可缓解 |
| **漏报** | 隐晦表达（"想休息"） | 高 | 关键词已包含隐晦表达 |
| **误判** | 反讽/玩笑 | 中 | Qwen3 上下文理解 |
| **漏报** | 方言/网络用语 | 中 | 关键词表有限 |
| **误判** | Qwen3 模型幻觉 | 中 | 0.6B 模型能力有限 |
| **漏报** | 非中文表达 | 低 | 当前仅支持中文 |

### 4.5 提高准确率建议

1. **升级本地模型** — Qwen3-1.7B 或 4B 效果显著优于 0.6B
2. **添加用户反馈** — 允许用户标记"误报/漏报"，持续优化
3. **多语言支持** — 添加英文情感词典
4. **定期更新关键词** — 跟踪网络新词/隐晦表达
5. **人工审核机制** — 高风险结果可选择发送给指定联系人

## 总结

### 项目优势

1. **功能全面** — 市场上功能最完整的心理健康桌面应用
2. **隐私优先** — 数据完全本地化，支持离线使用
3. **科学依据** — 基于 C-SSRS、PHQ-9、GAD-7 等金标准
4. **免费开源** — 无订阅费，无广告
5. **技术先进** — Electron + React + 本地 AI 模型

### 主要风险

1. **安全** — API Key 明文存储、open-external 无验证
2. **准确率** — 0.6B 模型能力有限，可能误判
3. **无移动端** — 大多数用户习惯移动端
4. **无临床验证** — 缺乏专业机构背书
5. **测试覆盖** — 零测试，质量保障不足
