# FriendOS 赛前升级计划

## 背景

FriendOS 参加广州大学庆园杯"AI心理健康陪伴与早期风险识别助手"创新应用大赛。当前项目底层架构扎实，但存在以下短板：各模块风险信号未聚合、AI 聊天与危机干预未打通、部分服务代码已写但未接入前端、UI 缺少关键操作的微交互反馈。本计划聚焦于补齐核心闭环和演示体感。

---

## Phase 1：统一风险画像（核心赛点，最高优先级）

### 1.1 综合风险评分引擎

在 Electron 主进程新建 `RiskScoringEngine.cjs`，融合以下信号源计算 0-100 综合风险指数：

| 信号源 | 权重 | 数据来源 |
|--------|------|----------|
| 情绪分析（ONNX + 关键词） | 30% | `emotionRecords` 表 |
| 行为异常（个人基线偏离） | 25% | `BehaviorAnalyzer` 输出 |
| 评估量表（PHQ-9/GAD-7/PSS-10） | 25% | `assessments` 表 |
| 聊天情感检测 | 10% | `conversationSummaries` 表 |
| 日记情绪趋势 | 10% | `diaries` 表 mood 字段 |

风险等级映射：0-25 低 / 26-50 中低 / 51-75 中 / 76-90 高 / 91-100 危急

注册 IPC handler：`risk:calculate`、`risk:getTrend`（近 7/30 天）

### 1.2 新建综合风险仪表盘页面

新建 `RiskDashboardPage.tsx`（路由 `/risk`），包含：

- **综合风险评分卡片**：大字数字 + 颜色指示（绿/黄/橙/红）+ 数字滚动动画
- **六维雷达图**（Recharts RadarChart）：情绪/行为/社交/睡眠/压力/自理，数据来自 `healthProfiles`
- **风险趋势折线图**（Recharts LineChart）：近 7 天/30 天切换
- **各信号源状态列表**：每项显示最新值和变化方向（上升箭头/下降箭头）
- 在侧边栏 `nav.dashboard` 下方增加 `/risk` 入口

### 1.3 风险自动触发通知

改造 `NotificationService.cjs`：

- 新增 `checkRiskAndNotify` 方法，每次风险评分计算后调用
- 规则：风险等级从中以下升到中以上 → 推送系统通知"近期状态有变化，建议关注"
- 连续 3 天行为异常 → 推送"已经好几天没写日记了，要不要聊聊？"
- 风险等级达到高/危急 → 推送并自动弹出 `CrisisInterventionModal`
- 在仪表盘和风险页面顶部显示通知横幅

## Phase 2：打通数据闭环（AI + 情绪 + 记忆）

### 2.1 日记保存时自动触发情绪分析

改造 `useDiary.ts` 的保存逻辑：

- 保存日记后，调用 `sentiment-analyze` IPC 分析日记内容
- 将分析结果写入 `emotionRecords` 表（source: 'diary'）
- 同时调用 `behavior:analyzeDaily` 更新当日 `behaviorRecords`
- 调用 `risk:calculate` 重算风险评分

### 2.2 AI 聊天中实时危机检测

改造 `useAI.ts` 的 `sendMessageStream`：

- 每收到一个 chunk，用关键词扫描检测危机词（复用 `SentimentService.cjs` 的 `CRISIS_KEYWORDS`）
- 检测到危机词 → 立即调用 `crisisStore.show('high', 'chat', matchedContent)`
- 聊天结束后，调用 `sentiment-analyze` 分析完整对话，写入 `emotionRecords`（source: 'chat'）

### 2.3 补全 ContextService → SystemPrompt 注入

改造 `ContextService.ts` 的 `fetchContext`：

- 将已有的 `semesterInfo` 和 `implicitHints` 加入返回值（当前已有但未注入）

改造 `prompts.ts` 的 `buildSystemPrompt`：

- 接收并注入 `semesterInfo`（学期阶段 + 压力指数）
- 接收并注入 `implicitHints`（蓄意表达检测结果）
- 在系统指令中增加："当前学期阶段：{semesterInfo}" 和 "用户最新日记可能有含蓄表达：{implicitHints}"

### 2.4 聊天结束后自动提取记忆候选

改造 `ConversationMemory.ts` 的 `saveConversationSummary`：

- 保存摘要后，提取关键信息作为 `MemoryCandidate`（status: 'pending'）
- 来源标记为 sourceType: 'chat'，使用现有 `db.memoryCandidates` 表

### 2.5 打字行为数据采集（轻量接入）

改造日记编辑器 `DiaryEditor.tsx`：

- 在编辑器内监听 keydown/keyup，采集：输入速度（字符/分钟）、删除键比例、停顿次数（>2秒无输入）
- 保存日记时将打字行为数据传给 `behavior:analyzeTyping` IPC
- 分析结果写入当日 `behaviorRecords` 的扩展字段

## Phase 3：UI 微交互增强（演示体感）

### 3.1 任务完成反馈

改造任务组件中 checkbox 点击逻辑：

- 点击完成时：checkbox 图标缩放弹跳（scale 1→1.3→1）+ 文字划线过渡（width 0→100%）
- 全部今日任务完成时：顶部出现一条绿色进度条填满动画 + "今日任务全部完成" 提示

实现方式：纯 CSS `@keyframes`，不引入额外库。

### 3.2 习惯打卡反馈

改造习惯打卡按钮：

- 打卡瞬间：圆环进度从当前值动画填充到新值（CSS `stroke-dashoffset` 过渡）
- 连续天数变化：数字从旧值滚动到新值（JS `requestAnimationFrame` 计数器）

### 3.3 AI 聊天流式呈现优化

改造 `ChatPanel.tsx` 消息渲染：

- 助手消息气泡：从底部 `translateY(8px)` 滑入 + 渐显
- 流式输出时：末尾显示闪烁光标（`|` 字符，CSS blink 动画）
- 用户消息：从右侧滑入

### 3.4 危机干预弹窗视觉强化

改造 `CrisisInterventionModal.tsx`：

- 弹窗外层加红色脉冲边框（`box-shadow` 呼吸灯动画，1.5s 循环）
- 背景遮罩从普通 `bg-black/30` 改为红色调 `bg-red-900/20`
- 与普通 Modal 的视觉语言明确区分开

### 3.5 数据变化数字动画

新建 `AnimatedNumber.tsx` 工具组件：

- 接收 `value` prop，旧值→新值时用 `requestAnimationFrame` 线性插值滚动
- 用于仪表盘统计数字、风险评分、完成率等场景

### 3.6 列表操作反馈

- 删除任务/记忆/日记时：元素向左滑出 + 高度收缩（CSS transition）
- 新建任务/记忆时：从顶部滑入 + 高亮闪烁一次

## Phase 4：演示准备与合规

### 4.1 完善 Demo 数据场景

改造 `seedDemoData.ts`，构造一个完整的"用户使用一周"故事线：

- Day 1-3：正常使用，心情 4-5 分，任务完成率高
- Day 4-5：心情下降到 2-3 分，任务完成率骤降，日记字数减少，出现"好累""不想动"
- Day 6：日记出现"活着没意思" → 触发危机干预
- Day 7：AI 聊天中主动关心 → 展示上下文感知
- 同时生成对应的行为记录、情绪记录、评估数据

### 4.2 隐私与伦理合规

- 首次使用 WelcomePage 增加"隐私知情同意"步骤：说明数据存储在本地、不上传、不替代专业诊疗
- 设置页增加"数据导出"（JSON 格式导出所有 IndexedDB 数据）
- AI 聊天和评估页面底部固定显示"本应用不替代专业心理诊疗"免责声明
- `settings.ai_tone` 选择 counselor 模式时，额外弹窗提示"AI 不具备心理咨询师资质"

## 测试计划

### 功能测试
- 风险评分：验证各信号源权重和等级映射正确
- 日记保存：确认自动触发情绪分析并写入 emotionRecords
- AI 聊天危机词检测：输入"不想活了"等关键词，验证弹窗触发
- 通知推送：风险等级变化时验证系统通知弹出
- 打字行为采集：写日记时验证速度/删除率/停顿数据记录

### UI 测试
- 任务完成动画在亮色/暗色主题下正常
- 危机弹窗脉冲效果不影响可读性
- 数字动画在快速连续更新时不会闪烁
- 所有动画在 `prefers-reduced-motion` 下被禁用
- 移动端视口下布局不溢出

### 演示测试
- 完整走一遍 Demo 数据场景，验证故事线流畅
- 从仪表盘→风险页面→情绪页面→AI 聊天→危机干预的完整流程无卡顿
- 首次打开→隐私同意→引导教程→进入主界面的流程完整

---

## 默认假设与约束

- 不引入新的 npm 依赖，所有动画用 CSS + 原生 JS 实现
- 风险评分权重为初始值，后续可根据实际数据调优
- 打字行为采集仅在日记编辑器中进行，不采集其他页面
- 数据导出为 JSON 格式，不做加密（本地数据无敏感云数据）
- 不改动现有数据库 schema 版本，所有新字段使用已有表的扩展
