1. `SentimentService.cjs:31-37`：23 个关键词（`想死, 不想活, 活不下去, 死了算了, 去死, 一了百了, 自杀, 自残, 割腕, 跳楼, 结束生命, 遗书, 告别, 准备去死, 想消失, 离开这个世界, 活着没意思, 解脱, 撑不下去, 活够了, 没意义, 没有意义`）
2. `ChatPanel.tsx:13-20`：30+ 个关键词（包含 SentimentService 的所有 + 额外的 `吃药, 轻生, 寻死, 赴死, 死掉, 死吧` 等）
3. `RiskScoringEngine.cjs:218,272`：5 个关键词（`想死, 不想活, 自杀, 结束生命, 活着没意思`）

**修改内容**：
1. 创建统一的危机关键词配置文件：`pc/src/config/crisisKeywords.ts`
2. 导出 `CRISIS_KEYWORDS` 数组（合并三处，去重，取并集）
3. `SentimentService.cjs`、`ChatPanel.tsx`、`RiskScoringEngine.cjs` 都从配置文件导入
4. 这样答辩时可以说"统一的危机词库，一处维护，全局生效"

### B3. 添加否定词处理到 SentimentService

**当前状态**：`SentimentService.cjs:6` 注释写着"不做否定检测（安全第一，宁可误报不漏报）"
- 问题：误报率太高，"不想活了这种无聊的课"也会触发危机

**修改内容**：
1. 在 `keywordScan()` 函数（L61-96）中添加否定词窗口检测
2. 否定词列表：`['不', '没', '别', '勿', '未', '莫', '非', '无']`
3. 规则：如果关键词前 3 个字符内出现否定词，且否定词后没有句号/感叹号/问号分隔，则标记为"否定上下文"
4. 否定上下文中的危机关键词仍保留（安全第一），但降低置信度：
   - 正常命中：`crisisLevel = 3`
   - 否定上下文命中：`crisisLevel = 1`（降为"疑似"，需要 LLM 确认）
5. 这样既保持"宁可误报不漏报"的安全原则，又给 LLM 留出判断空间

## 阶段 C：危机检测增强（P1 — 加分项）

### C1. ChatPanel 危机检测改为调用 SentimentService

**当前状态**：`ChatPanel.tsx:22-24`
```ts
function hasCrisisContent(text: string): boolean {
  return CRISIS_WORDS.some(word => text.includes(word));
}
```
- 纯关键词匹配，直接弹窗
- 与 SentimentService 的三层分析完全脱节

**修改内容**：
1. `ChatPanel.tsx` 中移除本地 `CRISIS_WORDS` 和 `hasCrisisContent()`
2. 改为调用 `window.electronAPI.sentimentAnalyze(text)`（已有 IPC）
3. 根据返回的 `level` 判断是否触发危机：
   - `level === 'high'` → `showCrisis('high', 'chat', text)`
   - `level === 'medium'` → 不弹窗，但记录到 emotionRecords
4. 这样 ChatPanel 的危机检测也走三层分析（关键词→ONNX→Qwen3）

### C2. RiskScoringEngine 危机关键词增加排除规则

**当前状态**：`RiskScoringEngine.cjs:218-228, 272-282`
- 聊天和日记中的危机关键词检查都是简单的 `includes()` 匹配

**修改内容**：
1. 在 `calculateChatScore()` 和 `calculateDiaryScore()` 中添加排除规则：
   - 检测引号内容（`"` 或 `「」` 包裹的文本）→ 跳过
   - 检测已知误报模式：`无聊到想死`, `困死了`, `笑死了`, `开心死了`, `吓死了`, `急死了`
   - 检测成语/俗语：`九死一生`, `生不如死`, `死里逃生`, `置之死地而后生`
2. 排除规则不删除关键词匹配，而是在匹配后过滤

### C3. SentimentService Qwen3 prompt 增加上下文

**当前状态**：`SentimentService.cjs:134-153`
- systemPrompt 只告诉 LLM 判断标准
- userMessage 只包含当前文本 + 情感分析结果 + 关键词

**修改内容**：
1. 在 `qwenAnalyze()` 的 `context` 参数中增加：
   - 用户最近 3 天的情绪基线（从 BehaviorAnalyzer 获取）
   - 当日日记全文（如果有的话）
   - 最近 3 轮对话摘要（从 ConversationMemory 获取）
2. 在 userMessage 中注入这些上下文：
   ```
   用户近3天平均心情：3.2/5（基线4.1）
   今日日记摘要：考试压力大...
   最近对话：用户提到最近失眠...
   ```
3. 这样 LLM 可以更准确地区分"真实危机"和"情绪宣泄"
