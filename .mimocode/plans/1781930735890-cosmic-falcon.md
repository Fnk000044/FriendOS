## 修复 A：通知提醒恢复初始化后未删除

**根因**：`handleReset` 清除 localStorage 并调用 `notificationStore.reset()`，将 `initialized` 设为 `false`。但当用户重新走完欢迎流程后，`NotificationSettings` 的 `useEffect` 调用 `initFromStorage()`，发现 `initialized === false`，于是从空的 localStorage 重新加载 `DEFAULT_REMINDERS`（默认的两条提醒）。

**方案**：在 `initFromStorage()` 中检查一个独立的"已重置"标记，如果存在则加载空数组而非默认值。

**修改文件**：
- `E:\FriendOS\pc\src\stores\notificationStore.ts`
  - `initFromStorage()` 开头检查 `localStorage.getItem('friendos_reset_flag')`
  - 如果存在：设 `reminders: []`, `initialized: true`，删除该 flag，return
- `E:\FriendOS\pc\src\pages\SettingsPage.tsx`
  - `handleReset` 中在清除 localStorage **之前**设置 `localStorage.setItem('friendos_reset_flag', '1')`
  - 注意：`friendos_reset_flag` 不以 `friendos_` 开头的会被清除... 等等，它确实以 `friendos_` 开头。需要用不同的 key 前缀，如 `system_reset_flag`。

**关键顺序**：
```
1. localStorage.setItem('system_reset_flag', '1')  // 不会被 friendos_ 过滤器清除
2. db.delete()
3. 清除 friendos_*/lifeos_*/use_* 的 localStorage
4. notificationStore.reset()  // 只清内存状态
5. useLanguage.reset()
// 不调用 window.location.reload()，由 reset 触发 welcome 页面
```
